FIRST BOARD AND ENGINE LATENCY
Fixed a repeated stability-timer reset: if another capture arrived before the
24 ms interval elapsed, the old path ran recognition again and replaced the
candidate's timestamp. A stream of frequent frames could indefinitely postpone
the first board. Pending candidates now keep their original timestamp until
confirmed or invalidated by an actual pixel change. Confidence thresholds,
plausibility checks and legal-position validation are unchanged.

Production reader/service tests cover an untouched opening-board crop, a full
screen retained without new captures, rapid confirmation polling, and a phone
portrait fixture with both board orientations. The screenshot artwork comes
from the existing desktop regression fixtures. These are host simulations.

The move adapter streams from the first legal depth-one result while preserving
the selected time/depth limit. The completed main move is published before
optional continuation searches, even with early suggestions off. UCI thread,
hash and strength options warm before the first position, and unchanged options
skip a redundant ready handshake. Stockfish and evaluation remain independent.

Six real Stockfish 19 searches through the production Java adapter on the Mac
host showed early legal moves in roughly 1–14 ms and completion near the chosen
500 ms budget. This measures engine-to-callback time, not phone recognition or
compositor latency. Protocol tests hold bestmove/reply responses back to verify
that early/root callbacks are not blocked and the selected budget is unchanged.
A service regression also checks Only my color with Steady arrows: an invisible
opponent line must not block the first available arrow for the user’s color.

Single-move synchronization checks all legal single moves before two-move
recovery. A separate same-JVM benchmark checked 246 successor positions: the
old order took 63–217 ms total, the new order 3–13 ms total in four warmed runs.
Those are component totals under host load, not A35 per-move latency.

The optional real Stockfish test uses BOARDLENS_STOCKFISH_TEST_ENGINE. Together
with the three real-Maia tests, it runs locally when its files are provided;
CI without those external files skips seven tests in this version. The complete release APK
includes all twelve Tiny bots and all on-phone engine adapters, preserves its
release signing identity, and passes 16 KB native/ZIP alignment checks.

MAIA PERFORMANCE AND TIME CONTROLS — ANDROID 1.8.3
All four Maia move models show the same saved thinking-time control. For Maia,
the budget starts before the main inference and limits additional reply passes.
The first pass is always delivered, even if it exceeds the budget; an in-flight
reply may finish after the deadline. No repeated identical inference, arbitrary
wait, deeper-search claim or automatic engine/model switching is added. Maia
evaluation still uses one value pass and has no fictitious search-time field.

Selected Maia weights/vocabulary are prepared on the engine worker while the
scanner starts. A bounded LRU cache keeps 64 immutable, complete move rankings,
keyed by model, encoded rating, threads and full FEN. It supports different
alternative counts and reuses positions previously evaluated for prediction.
Close clears the cache and session. ONNX idle thread spinning is disabled to
reduce contention with recognition/evaluation when multiple threads are used.
The official model files, hashes, policy order and values are unchanged.

The real-model before/after host benchmark used seven repeated searches per
model with different alternative counts. Median repeat times on the Mac host:
  Maia 2:      4.430 ms before; 0.007 ms with a cache hit
  Maia 3 5M:   7.417 ms before; 0.008 ms with a cache hit
  Maia 3 23M: 16.242 ms before; 0.006 ms with a cache hit
  Maia 3 79M: 29.552 ms before; 0.007 ms with a cache hit
These are cache-hit/component times, not new-position inference speedups or
phone screen-to-arrow timing. First cold loads still took roughly 100–800 ms
on this host; preparing them overlaps scanner startup rather than eliminating
the work. Larger models still cost more for uncached positions.

Tests verify all four timer fields save, preserve the independent evaluator
and leave search-depth preferences intact. Controlled-clock real-model tests
verify budget exhaustion still publishes the main move, extra budget permits
replies, an actual predicted position needs no new inference, a changed rating
misses the cache, and 70 different inputs retain at most 64 cache entries and
release them on close. The 52 reference-position top-move checks and repeated-value checks still pass.
No physical A35 timing or installation is inferred from these host results.
